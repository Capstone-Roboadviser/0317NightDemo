# 조합 탐색 가이드

## 이 문서의 위치

현재 서비스의 런타임 조합 탐색은 `portfolio_service.py` 안의 **대표 종목 선택 로직**이 담당합니다.

이 문서는 그 배경 개념을 정리한 참고 문서입니다.

즉 현재 실제 런타임은:

- 섹터별 후보 종목군 보유
- 섹터당 대표 종목 1개 선택
- 조합별 최대 Sharpe 비교
- 최고 조합 선택

구조로 동작합니다.

## 현재 조합 탐색 문제 정의

현재 시스템은 아래 문제를 풉니다.

1. 각 섹터에서 대표 종목 1개를 고른다.
2. 그렇게 만들어진 대표 종목 조합마다 최대 Sharpe 포트폴리오를 계산한다.
3. 가장 좋은 Sharpe를 만든 조합을 선택한다.
4. 선택된 조합으로 Efficient Frontier 전체를 계산한다.

즉 이것은 아래 두 단계가 결합된 구조입니다.

- 상위 문제: 섹터별 대표 종목 선택
- 하위 문제: 선택된 대표 종목 유니버스에 대한 포트폴리오 최적화

## 현재 규칙

- 섹터당 대표 종목 수: `1`
- 전수 탐색 임계치: `5000`
- 샘플링 개수: `1000`
- 샘플링 seed: 고정
- 최소 유효 이력: `252` 영업일

## 현재 평가 기준

각 조합은 아래 기준으로 평가됩니다.

- long-only
- 종목 최대 비중 `35%`
- 평균 종목 상관관계 상한 `0.25`
- 목표 함수: Sharpe Ratio 최대화

즉 상관관계는 별도 목표가 아니라, Sharpe를 최적화하는 과정에서 함께 제약으로 작동합니다.

## 현재 코드 위치

- 런타임 대표 종목 선택: `app/services/portfolio_service.py`
- 과거 조합 탐색 스캐폴드: `app/services/combination_search_service.py`

`combination_search_service.py`는 원래 “섹터 내부에서 여러 종목을 뽑아 섹터 바스켓을 만드는 실험”에 가까웠고, 현재 메인 서비스는 그보다 단순한 “섹터당 대표 종목 1개” 구조를 사용합니다.

## 이후 확장 방향

나중에 조합 탐색을 더 고도화하려면 아래 방향이 가능합니다.

1. 대표 종목 1개 -> 상위 2개 선택으로 확장
2. sector cap 추가
3. soft-penalty 기반 상관관계 제약
4. 기대수익률 모델 교체
5. 배치 기반 장시간 탐색
